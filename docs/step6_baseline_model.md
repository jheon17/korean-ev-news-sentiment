# 6단계: 기준 모델

## 1. 목적

복잡한 모델을 사용하기 전에 간단한 키워드 규칙 기반 분류기를 만든다.

이 기준 모델은 성능이 아주 높을 필요는 없다.
나중에 GPT API나 다른 모델을 사용할 때 “단순 규칙보다 나은가?”를 비교하기 위한 기준선이다.

> **현재 상태 안내:** 아래 성능은 `gold_label` 재검토 전 초기 실험 기록이다.
> 이후 35건의 `gold_label` 재검토를 완료했으므로 기록된 수치를 현재 성능으로 해석하지 않으며,
> 새 평가 데이터를 구성한 뒤 다시 평가할 예정이다.

## 2. 쉬운 개념 설명

기준 모델은 뉴스 제목과 요약문에서 특정 단어를 찾고 점수를 매긴다.

예를 들어 `충전소 확대`, `보조금 확대`, `가격 인하` 같은 단어가 있으면 긍정 점수를 준다.
반대로 `화재`, `리콜`, `보조금 축소`, `판매 부진` 같은 단어가 있으면 부정 점수를 준다.

긍정 점수가 더 높으면 `긍정`,
부정 점수가 더 높으면 `부정`,
점수가 같거나 근거가 없으면 `중립`으로 분류한다.

## 3. 사용자가 먼저 생각할 질문

1. 키워드만으로 기사 맥락을 충분히 이해할 수 있는가?
2. `화재 대응 시스템 구축`처럼 부정 단어와 긍정 맥락이 함께 있는 경우를 규칙이 잘 처리할 수 있는가?
3. 기준 모델이 틀린 사례를 보고 라벨 가이드나 키워드 규칙을 어떻게 고칠 수 있는가?

## 4. 최소 실행 코드

먼저 라벨링 파일의 형식을 확인한다.

```powershell
uv run python src/validate_labels.py
```

그다음 기준 모델을 실행한다.

```powershell
uv run python src/rule_based_baseline.py
```

출력 파일은 다음 위치에 생성된다.

```text
data/predictions/rule_based_predictions_20260803.csv
reports/rule_based_baseline_report_20260803.txt
```

## 5. 결과 해석 방법

이번 평가는 `dev` 데이터만 사용한다.
`final_test` 데이터는 마지막 평가 전까지 성능 비교나 규칙 수정에 사용하지 않는다.

확인할 지표는 다음과 같다.

- Accuracy
- Macro-F1
- 클래스별 Precision
- 클래스별 Recall
- 클래스별 F1
- 혼동행렬

Accuracy는 전체 중 몇 개를 맞혔는지 보여준다.
Macro-F1은 긍정, 중립, 부정을 균형 있게 잘 맞혔는지 보여준다.

## 6. 오류, 편향, 데이터 누수 가능성

키워드 규칙은 문맥을 잘 이해하지 못한다.

예를 들어 `화재 대응 시스템 구축`은 안전 관리 강화라는 긍정 맥락일 수 있지만,
단순 규칙은 `화재`라는 단어 때문에 부정으로 판단할 수 있다.

반대로 `확대`라는 단어가 있어도 전기차 시장에 직접 좋은 영향이 아닐 수 있다.

최종 테스트용 라벨을 보고 키워드를 수정하면 데이터 누수가 생긴다.
키워드 수정과 오류 분석은 개발용 데이터만 보고 진행해야 한다.

## 7. 완료 조건

6단계는 다음 조건을 만족하면 완료된다.

- 라벨링 CSV의 라벨 형식이 검증되어 있다.
- 키워드 규칙 기반 분류기가 실행된다.
- 예측 결과 CSV가 생성되어 있다.
- dev 데이터 기준 평가 리포트가 생성되어 있다.
- Accuracy 외에 Macro-F1과 클래스별 지표를 확인했다.
