# 4단계: 전처리

## 1. 목적

네이버 뉴스 검색 API에서 받은 원본 데이터를 사람이 라벨링하고 모델이 사용할 수 있는 형태로 정리한다.

원본 데이터는 `data/raw/`에 그대로 보존하고,
전처리한 데이터는 `data/processed/`에 따로 저장한다.

## 2. 쉬운 개념 설명

전처리는 수집한 데이터를 분석하기 좋은 형태로 정리하는 작업이다.

네이버 뉴스 검색 결과의 제목과 요약문에는 `<b>전기차</b>` 같은 HTML 태그가 들어 있을 수 있다.
또 `&quot;` 같은 HTML 엔티티가 들어 있어 사람이 읽기 불편할 수 있다.

이번 단계에서는 이런 표시를 제거하고, 날짜 형식을 일정하게 바꾸고, 같은 뉴스가 여러 검색어에서
반복 수집된 경우를 원문 링크 기준으로 정리한다.

## 3. 사용자가 먼저 생각할 질문

1. 같은 원문 링크가 여러 검색어에서 수집되면 하나의 기사로 볼 것인가?
2. 제목이 거의 같지만 원문 링크가 다른 기사는 중복 후보로만 확인할 것인가?
3. 제목이나 요약문이 비어 있는 기사는 바로 삭제하지 않고 먼저 개수를 확인할 것인가?

이번 단계에서는 다음 기준으로 진행한다.

- 같은 원문 링크는 하나의 기사로 본다.
- 거의 같은 제목은 자동 삭제하지 않고 리포트에서 확인한다.
- 제목과 요약문 결측은 바로 삭제하지 않고 개수만 확인한다.

## 4. 최소 실행 코드

아래 명령으로 전처리를 실행한다.

```powershell
uv run python src/preprocess_news.py
```

입력 파일은 다음이다.

```text
data/raw/naver_news_sample_20260803.csv
```

출력 파일은 다음이다.

```text
data/processed/naver_news_sample_20260803_preprocessed.csv
data/processed/preprocessing_report_20260803.txt
```

## 5. 처리 내용

이번 단계에서 처리하는 내용은 다음과 같다.

- 제목의 HTML 태그 제거
- 요약문의 HTML 태그 제거
- HTML 엔티티 변환
- 발행일을 ISO 형식 날짜로 변환
- 원문 링크 기준 중복 제거
- 검색어별 중복 수집 확인
- 제목 결측 확인
- 요약문 결측 확인
- 정규화 후 동일한 제목 확인

전처리 CSV에는 다음 열을 저장한다.

- search_query
- matched_queries
- duplicate_count
- collected_at
- title
- description
- originallink
- link
- pubDate
- pubDate_iso

`matched_queries`는 같은 기사가 어떤 검색어에서 함께 잡혔는지 보여준다.
`duplicate_count`는 같은 원문 링크로 몇 번 수집되었는지 보여준다.

## 6. 결과 해석 방법

원본 행 수보다 전처리 후 행 수가 줄었다면 같은 원문 링크가 여러 번 수집된 것이다.

결측 제목이나 결측 요약문이 많으면 라벨링 품질이 떨어질 수 있다.

날짜 변환 실패가 있으면 원본 `pubDate` 형식이 예상과 다르다는 뜻이다.

정규화 후 동일한 제목이 있으면 같은 기사이거나 매우 비슷한 보도일 가능성이 있다.
하지만 링크가 다르면 언론사별 재전송 기사일 수도 있으므로 이번 단계에서는 자동 삭제하지 않는다.

## 7. 오류, 편향, 데이터 누수 가능성

HTML 태그 제거 과정에서 제목의 일부 문자가 의도치 않게 사라질 수 있다.

원문 링크 기준 중복 제거는 간단하고 안전한 기준이지만,
서로 다른 언론사가 같은 내용을 거의 동일하게 보도한 경우까지 제거하지는 못한다.

전처리 단계에서 라벨을 미리 예측하거나 사람이 붙인 정답을 사용하면 데이터 누수가 생길 수 있다.
이번 단계에서는 라벨 정보를 사용하지 않는다.

## 8. 완료 조건

4단계는 다음 조건을 만족하면 완료된다.

- 원본 데이터가 `data/raw/`에 보존되어 있다.
- 전처리 데이터가 `data/processed/`에 별도로 저장되어 있다.
- 제목과 요약문에서 HTML 태그가 제거되어 있다.
- 날짜 형식이 통일되어 있다.
- 원문 링크 기준 중복 제거가 수행되어 있다.
- 결측 제목과 결측 요약문 개수를 확인했다.
- 검색어별 중복 수집 가능성을 확인했다.

2026년 8월 3일에 샘플 CSV 전처리를 실행했다.

- 입력 파일: `data/raw/naver_news_sample_20260803.csv`
- 출력 파일: `data/processed/naver_news_sample_20260803_preprocessed.csv`
- 리포트 파일: `data/processed/preprocessing_report_20260803.txt`

| 원본 행 수 | 60 |

| 원문 링크 기준 제거된 중복 행 수 | 25 |
| 결측 제목 수 | 0 |
| 결측 요약문 수 | 0 |

| 정규화 후 동일한 제목 종류 수 | 0 |

제목과 요약문에서 `<b>` 태그는 제거되었고,
`&quot;` 같은 HTML 엔티티는 사람이 읽을 수 있는 문자로 변환되었다.

중복 제거 결과를 보면 같은 뉴스가 여러 검색어에서 함께 수집되는 경우가 있었다.
따라서 이후 분석에서는 원본 행 수가 아니라 전처리 후 기사 수를 기준으로 해석해야 한다.
