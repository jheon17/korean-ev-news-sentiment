전기차 뉴스 감성 분류: 공개 뉴스 기반 방법론 재구현

네이버 뉴스 검색 API로 수집한 전기차 관련 한국어 뉴스의 제목과 요약문을 이용해 국내 전기차 시장 전체에 미칠 영향을 긍정, 중립, 부정으로 분류한 학습 프로젝트다.

작성일2026년 8월 3일
분석 범위한국어 뉴스, 국내 시장 기준
평가 기준dev 데이터 28건

요약: 무엇을 만들었고 어디까지 확인했나

이 프로젝트의 목표는 뉴스 문장의 분위기가 아니라, 뉴스가 국내 전기차 시장의 수요·보급·등록대수에 줄 예상 영향을 분류하는 것이다.

공개 뉴스 검색 결과를 수집하고, 원본 보존과 전처리를 거친 뒤, 사람이 만든 정답 라벨을 기준으로 세 가지 분류 방식을 비교했다.

현재 dev 데이터 기준으로는 GPT API 모델이 가장 좋은 성능을 보였다. Accuracy는 0.643, Macro-F1은 0.653이었다.

초심자를 위한 핵심 개념

감성은 기분이 아니라 시장 영향이다

일반적인 감성 분석은 문장이 밝은지 어두운지 판단하는 경우가 많다. 이 프로젝트에서는 다르게 본다. 기준은 “이 뉴스가 국내 전기차 시장에 좋은 조건을 만드는가, 나쁜 조건을 만드는가, 아니면 영향이 불명확한가”다.

라벨뜻예시
긍정전기차 수요, 보급, 등록 증가 가능성을 높이는 뉴스보조금 확대, 충전소 확대, 가격 인하, 배터리 안전성 개선
중립영향이 불명확하거나 단순 사실 전달에 가까운 뉴스행사 소개, 해외 시장 중심 기사, 특정 기업 소식
부정수요 감소 또는 위험 증가 가능성을 높이는 뉴스화재, 리콜, 보조금 축소, 충전 불편, 비용 상승

왜 사람 정답 라벨이 필요한가

모델이 예측한 결과가 맞는지 판단하려면 비교 대상이 필요하다. 그 비교 대상이 사람이 직접 붙인 gold_label이다. 모델 결과는 pred_label로 저장하고, 두 값을 비교해 성능을 계산한다.

프로젝트 진행 과정

1. 문제 정의국내 전기차 시장 전체 영향으로 라벨 기준을 고정했다.
2. API 연결네이버 뉴스 검색 API 연결을 10건 호출로 확인했다.
3. 데이터 수집검색어 6개로 각 10건씩, 총 60건을 저장했다.
4. 전처리HTML 태그 제거, 날짜 통일, 중복 제거를 수행했다.
5. 정답 라벨사람이 긍정·중립·부정 라벨과 판단 이유를 입력했다.
6. 기준 모델간단한 키워드 규칙 모델을 만들었다.
7. 모델 확장Qwen 로컬 모델과 GPT API 모델을 구현했다.
8. 평가Accuracy, Macro-F1, 클래스별 지표를 비교했다.
9. 오류 분석GPT 오분류를 유형별로 분류했다.
다음 단계프롬프트 v2를 실행하고 최종 테스트를 마지막에만 사용한다.

데이터와 전처리 결과

네이버 API는 다운로드형 CSV가 아니라 검색 API다. 따라서 검색어, 수집일, 제목, 요약문, 원문 링크, 발행일을 직접 저장했다. 기사 본문 전체는 임의로 크롤링하지 않았다.

단계건수해석

전처리 후35원문 링크 기준 중복 25건을 제거했다.

dev 라벨 분포는 긍정 21건, 중립 3건, 부정 4건이다. 긍정이 많기 때문에 Accuracy만 보면 모델 성능을 과대평가할 수 있다.

GPT API 상세 결과와 의미

GPT API 모델은 gpt-5.6-luna를 사용했고, 출력은 JSON Schema로 고정했다. 즉 모델이 자유 문장을 길게 쓰더라도 최종 결과는 label, confidence, reason, evidence 형식으로 받도록 설계했다.

중요한 해석: GPT API는 틀릴 때 주로 긍정이나 부정을 중립으로 낮춰 판단했다. 이는 프롬프트에 “근거가 부족하면 중립”이라는 안전한 기준을 넣었기 때문이다.

프롬프트 반복 개선은 이렇게 작동한다

프롬프트 반복 개선은 틀린 사례를 보고 기준을 조금씩 명확히 만드는 과정이다. 무작정 좋은 문장을 추가하는 것이 아니라, dev 데이터의 오류 유형을 보고 고친다.

  1. v1 프롬프트로 분류한다. 국내 시장 전체 영향이 불명확하면 중립으로 두는 보수적 기준이었다.
  2. 오분류를 모은다. GPT API dev 결과에서 10건의 오분류가 확인됐다.
  3. 오류 유형을 나눈다. 긍정 개선 요소를 중립으로 과소평가한 사례가 6건으로 가장 많았다.
  4. 프롬프트 v2를 만든다. 충전, 안전, 고객 지원, 라인업 확대 같은 구매·이용 조건 개선은 긍정 후보라고 명시했다.
  5. v2를 다시 평가한다. v2가 긍정 Recall을 높이는지, 대신 중립 오판을 늘리지는 않는지 비교한다.
오류 유형건수프롬프트 개선 방향
긍정 개선 요소를 중립으로 과소평가6구매·이용 조건 개선은 직접 등록 증가가 없어도 긍정 후보로 본다.
국내 기준과 해외 시장 영향 혼재3해외 시장 중심 뉴스는 국내 영향이 드러나지 않으면 중립으로 본다.
부정 위험을 중립으로 과소평가1비용·안전·정책 위험은 소비자 신뢰 하락 가능성을 더 강하게 본다.

한계와 주의점

  • 데이터가 작다. 현재 전처리 후 35건이고, dev 평가는 28건이다. 최종 성능을 단정하기에는 작다.
  • 제목과 요약문만 사용했다. 본문 전체 맥락이 없어서 라벨이 애매한 기사가 생길 수 있다.
  • 검색어 편향이 있다. 예를 들어 배터리 화재 검색어는 부정 뉴스 비중을 높일 수 있다.
  • dev 데이터에 과적합될 수 있다. 프롬프트를 dev 오류에 맞춰 고치면 dev 점수는 좋아져도 새 데이터에서는 나빠질 수 있다.
  • final_test는 아직 사용하지 않았다. 마지막 평가 전까지 열어보거나 프롬프트 개선에 사용하면 안 된다.

앞으로 같은 방식을 따르면 어떤 결과를 기대할 수 있나

이 방식은 완성형 모델 하나를 바로 만드는 것이 아니라, 공개 데이터 기반으로 분류 기준과 평가 체계를 재현 가능하게 쌓아가는 접근이다.

  1. 데이터를 100~200건 이상으로 늘린다. 라벨 분포가 더 안정되면 평가 지표 신뢰도가 높아진다.
  2. v2 프롬프트를 dev 데이터에 실행한다. 긍정 Recall이 개선되는지, 중립 Precision이 더 나빠지지 않는지 본다.
  3. 오류 분석을 한 번 더 반복한다. 새 오류 유형이 생기면 v3 후보를 만든다.
  4. 프롬프트가 고정되면 final_test로 마지막 평가를 한다. 이 점수가 실제 프로젝트 성능에 더 가깝다.
  5. 개별 분류가 검증된 뒤 월별 감성 지수를 만든다. 예를 들어 `(긍정 기사 수 - 부정 기사 수) / 전체 기사 수`로 계산할 수 있다.

기대 결과는 “뉴스 수집, 전처리, 사람 라벨, 모델 예측, 평가, 오류 분석, 프롬프트 개선”이 하나의 재현 가능한 파이프라인으로 남는 것이다. 포트폴리오에서는 단순히 GPT를 호출했다는 점보다, 정답 데이터와 평가 지표로 모델을 검증했다는 점이 핵심 성과다.

최종 결론

현재 단계의 결론은 명확하다. 키워드 규칙과 Qwen 로컬 모델보다 GPT API 모델이 dev 데이터에서 더 안정적인 성능을 보였다. 그러나 GPT API도 긍정적인 시장 개선 요소를 중립으로 판단하는 경향이 있어, 프롬프트 v2를 통한 반복 개선이 필요하다.

이 프로젝트는 공개 뉴스 기반 전기차 시장 감성 분류를 재구현하는 학습 프로젝트로서, 데이터 수집부터 평가와 오류 분석까지의 전체 흐름을 갖췄다. 다음 성과 목표는 v2 프롬프트 평가, 라벨 데이터 확대, final_test 최종 평가, 월별 감성 지수 생성이다.
